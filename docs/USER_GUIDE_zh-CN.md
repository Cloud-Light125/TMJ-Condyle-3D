# TMJ-Condyle-3D 用户指南

这份指南描述从一例 MRI 到三维髁突预测的完整操作顺序。项目面向课设/实验，
不是临床诊断软件。

## 第一次使用

1. 安装 3D Slicer。
2. 双击项目根目录的“启动实验平台.bat”。
3. 按“首次使用引导”和首页的“下一步”提示操作。

不需要打开 PowerShell，不需要在 Slicer 的 Additional module paths 中添加目录，也不需要
手工运行 Python 或 nnU-Net 命令。若希望从桌面启动，可双击“创建桌面快捷方式.bat”。

## 你要准备什么

- Windows 电脑。
- 3D Slicer。
- 医院提供的 TMJ MRI；本项目不规定医院采集协议。
- 一位了解颞下颌关节解剖的医生/牙医负责人工标注。
- 训练默认使用 CPU；如果在训练页主动选择 GPU，则需要兼容当前运行环境的 NVIDIA CUDA GPU。

不要把患者原始文件放进 Git，也不要把患者姓名、PatientID、StudyInstanceUID、
AccessionNumber、出生日期或医院信息写入 case id、报告或图标题。

## 一个病例是什么

一个 TMJ 侧就是一个 case。建议使用 case_001、case_002 这样的匿名名称。左右侧
如果属于同一患者，要在私有 manifest 中使用相同 group_id，不能只因为文件名不同
就当成两个独立患者。

## 操作总览：只使用 GUI 也可以完成实验

启动后，平台顶部固定显示七个一级页面；每一页都可以点击“返回首页”：

- 首页：显示病例统计、训练状态和下一步建议。
- 病例与标注：导入 MRI、画笔/擦除、切片切换、3D 检查、保存和病例列表。
- 训练数据：只收状态为 VERIFIED（已确认）的病例，检查并准备真实训练数据。
- 模型训练：自动检查环境，后台执行官方 nnU-Net v2 3d_fullres 五折训练。
- 实验结果：查看真实 OOF 的 Dice、IoU、HD95、五折表格和病例级对比。
- 自动分割：用完整五折模型处理新的 MRI，并查看 mask 与 3D 髁突。
- 设置：查看项目位置和高级诊断信息。

一次完整实验的 GUI 顺序是：

1. 在“病例与标注”导入 MRI。
2. 用画笔把下颌髁突标出来；涂错时使用擦除，检查切片和 3D 后保存。
3. 点击“确认本例标注”；确认前不会进入正式训练。
4. 重复准备病例，至少需要五个不同患者组才能进行五折实验。
5. 在“训练数据”点击“检查全部病例”，确认每例都通过 QC。
6. 点击“准备训练数据”，平台调用现有数据构建脚本和 grouped 5-fold 脚本。
7. 进入“模型训练”，确认环境检查结果后点击“开始 5 折训练”。任务在后台运行，已完成的 fold 会保留。
8. 训练完成后，平台自动运行真实 OOF 预测和评价，在“实验结果”查看 Dice、IoU、HD95。
9. 在病例级结果中选择病例，查看 MRI + 人工标注 + 模型预测的 2D 或 3D 对比。
10. 在“自动分割”选择新的 MRI，生成预测 mask 并查看三维模型。

首页的“怎么做实验？”按钮会显示同样的新手流程。训练页的“CPU 测试流程”只检查
软件链路，不训练模型、不生成预测，也不生成 Dice、IoU 或 HD95。

## 状态含义

manifest 的 annotation_status 使用：

- NEW：已导入 MRI，还没有开始或完成标注。
- ANNOTATING：正在 Slicer 中标注。
- ANNOTATED：医生完成了 mask 导出。
- UNVERIFIED：发现了没有可信状态来源的 mask，必须人工核实来源。
- VERIFIED：第二位医生或项目负责人完成复核，可以进入正式训练。

只有 VERIFIED 且通过 QC 的病例才会进入训练数据集。ANNOTATED 只表示已保存，不能直接训练。

## 重要的真实限制

没有人工髁突 mask 时，整个项目可以检查软件链路，但不能报告正式模型结果。
只有少量病例时，结果应描述为初步可行性验证，不能写成临床泛化能力结论。
